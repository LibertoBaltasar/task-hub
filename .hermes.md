# Task Hub — Project Rules for Hermes

## When working in this repo

- **Language:** Spanish for all communication with Liberto; Kotlin for code
- **Architecture:** Compose Multiplatform with commonMain + platform modules
- **Structure:** `composeApp/` for the app, `docs/` for specs
- **Build:** `./gradlew build` before declaring anything done
- **Commits:** Atomic per feature, messages in Spanish, format: `feat: descripción` or `fix: descripción`
- **Branches:** `main` is production; feature branches as `feat/nombre-feature`
- **TDD:** Tests first, then implementation. Use `kotlin.test` for unit tests, Compose UI test for UI
- **Target platforms:** Priority = Android + iOS, Desktop secondary
- **Dependencies:** Add to `libs.versions.toml` (version catalog), never hardcode versions

## Spec workflow

1. Spec written in `docs/specs.md` → reviewed by Liberto
2. Approved → branch created → implementation → PR
3. Liberto reviews on GitHub and merges

## Liberto

- Experienced developer, concise style
- Reviews diffs on GitHub
- Manually tests on his devices
- Prefers Spanish in all communication
